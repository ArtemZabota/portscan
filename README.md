# portscan

Go-пакет TCP Connect-сканирования для встраивания в приложения. Использует только стандартную библиотеку Go **1.25.5**. CLI, HTTP-сервера, базы данных и внешних сервисов нет.

Пакет устанавливает обычное TCP-соединение и сразу закрывает его. Прикладные данные не отправляются. SYN/UDP-сканирование, raw sockets, определение ОС, обход фильтров и CIDR не реализованы.

## Использование

Установка пакета:

```sh
go get github.com/ArtemZabota/portscan
```

```go
package main

import (
    "context"
    "fmt"
    "log"
    "time"

    "github.com/ArtemZabota/portscan"
)

func main() {
    scanner, err := portscan.New(
        portscan.WithConcurrency(100),
        portscan.WithConnectTimeout(500*time.Millisecond),
        portscan.WithResolveTimeout(3*time.Second),
    )
    if err != nil {
        log.Print(err)
        return
    }

    ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
    defer cancel()

    ports := portscan.Union(
        portscan.Ports(22, 80, 443),
        portscan.Range(8000, 8010),
    )
    results, err := scanner.Scan(ctx, []string{"127.0.0.1", "::1", "localhost"}, ports)
    if err != nil {
        log.Print(err)
        return
    }

    for result := range results {
        fmt.Printf("host=%s ip=%s port=%d state=%s duration=%s err=%v\n",
            result.Host, result.IP, result.Port, result.State, result.Duration, result.Err)
    }
    if err := ctx.Err(); err != nil {
        log.Printf("Сканирование прервано; результаты неполные: %v", err)
    }
}
```

Для досрочного выхода из цикла обязательно вызовите `cancel()`. Можно продолжить читать канал до закрытия, если требуется дождаться завершения всех операций. Если результаты больше не нужны, после отмены читать канал необязательно.

## Публичный API

```go
func New(options ...Option) (*Scanner, error)
func WithConcurrency(n int) Option
func WithConnectTimeout(d time.Duration) Option
func WithResolveTimeout(d time.Duration) Option

func Ports(ports ...int) PortSet
func Range(first, last int) PortSet
func Union(sets ...PortSet) PortSet

func (*Scanner) Scan(
    ctx context.Context,
    hosts []string,
    ports PortSet,
) (<-chan Result, error)

type Result struct {
    Host     string
    IP       netip.Addr
    Port     uint16
    State    State
    Duration time.Duration
    Err      error
}

type State string
// Open, Closed, Timeout, Unreachable, Canceled, Error

type ValidationError struct {
    Field  string
    Reason string
}
```

`New()` использует лимит **64** операции, таймаут TCP **500 мс** и таймаут DNS **5 с**. Все три значения должны быть положительными; `nil` вместо опции считается ошибкой. Повторная опция заменяет предыдущее значение.

`Scanner` нужно создавать через `New`; нулевой экземпляр и `nil` возвращают ошибку из `Scan`. Постоянных фоновых горутин нет, метод `Close` не нужен. Один экземпляр разрешено использовать одновременно из нескольких горутин.

`PortSet` неизменяемый: конструкторы копируют входные значения, `Union` не меняет исходные наборы. Проверка значений выполняется в `Scan`, поэтому диапазоны удобно передавать прямо в вызов. Порты заданы типом `int`, чтобы значения `-1` и `65536` можно было отклонить до преобразования в `uint16`.

`IP` имеет тип `netip.Addr`: это неизменяемое значение без разделяемого среза байтов. При необходимости получить `net.IP` используйте `net.IP(result.IP.AsSlice())`. При ошибке DNS `IP.IsValid()` возвращает `false`.

`Duration` включает подключение и закрытие соединения. Для ошибки DNS это длительность разрешения имени, одинаковая для всех его портов. Ожидание лимита, очереди и читателя не учитывается; успешное разрешение DNS не входит во время TCP-проверки.

## Цели и порты

| Вход | Поведение |
| --- | --- |
| IPv4 или IPv6 | Подключение к указанному адресу; DNS не вызывается. IPv6 передаётся без квадратных скобок. |
| DNS-имя | ASCII-имя с метками до 63 байт и общей длиной до 253 байт без завершающей точки. Допустимы одиночные метки, например `localhost`, и IDN в Punycode. |
| Пустой список целей, пустой хост, пробелы, некорректный адрес | `*ValidationError`; ни одна проверка не запускается. Пробелы автоматически не удаляются. |
| `host:port`, URL, CIDR, IPv6 с зоной, Unicode DNS | `*ValidationError`; требуется отдельный хост и набор портов. |
| Некорректный адрес из цифр и точек, например `999.1.1.1` или `127.1` | Отклоняется при валидации, не передаётся в DNS. |
| Повторяющиеся IP | Проверяются один раз после канонизации; IPv4-mapped IPv6 приводится к IPv4. |
| Повторяющиеся DNS-имена | Регистр не учитывается. В `Host` остаётся первое написание. |
| `name` и `name.` | Разные цели: относительное и абсолютное имя могут разрешаться по-разному из-за DNS search domains. |
| Несколько A/AAAA-адресов | Все уникальные IP проверяются по всем выбранным портам. Имя разрешается один раз за один `Scan`, результат между сканированиями не кэшируется. |
| Разные имена или имя и IP, ведущие к одному адресу | Остаются разными целями, чтобы сохранить происхождение результата. |
| Имя не найдено или ответ не содержит пригодных IP | По одному `unreachable` на порт с недействительным `IP`. Другие цели продолжают сканироваться. |
| Таймаут / другая ошибка DNS | По одному `timeout` / `error` на порт; исходная ошибка сохранена в цепочке `Err`. |
| Порты `1..65535`, диапазон `a..b` | Допускаются; границы включены. |
| Порт `0`, отрицательный, больше `65535`, обратный диапазон | `*ValidationError`. |
| Повторяющиеся порты, пересечение диапазонов | Объединяются, каждый уникальный порт проверяется один раз на пару цель/IP. |
| Пустой `PortSet`, `Ports()` или `Union()` | `*ValidationError`. Пустой компонент внутри непустого `Union` допустим. |

Валидация всех целей и портов завершается синхронно до запуска сетевых операций. Список хостов после возврата из `Scan` можно изменять; во время самого вызова его нельзя изменять конкурентно.

## Состояния и ошибки

| Состояние | Значение |
| --- | --- |
| `open` | TCP handshake завершился успешно; соединение закрывается сразу. |
| `closed` | Система явно вернула отказ в подключении (`ECONNREFUSED` / `WSAECONNREFUSED`). |
| `timeout` | Истёк таймаут отдельного TCP/DNS-запроса или ОС сообщила таймаут. |
| `unreachable` | ОС сообщила недоступность узла/сети, либо DNS-имя не найдено. |
| `canceled` | Выполнявшаяся операция завершилась ошибкой после отмены или истечения срока родительского контекста. |
| `error` | Другая ошибка, например отказ в правах, исчерпание ресурсов или временная ошибка DNS. |

Классификация использует `errors.Is`, `errors.As`, `net.Error.Timeout`, `net.DNSError.IsNotFound` и системные коды. **Текст ошибок не сравнивается.** Для Windows предусмотрены собственные коды Winsock; поддерживаются также основные Unix-платформы. На остальных платформах неизвестные системные ошибки возвращаются как `error`.

Недоступность сети не выводится из одного только отсутствия ответа: если ОС не сообщила причину и время истекло, результат будет `timeout`. Успешный handshake сохраняет состояние `open`, даже если отмена пришла сразу после него. Ошибка `Close`, если возникнет, доступна через `Err`, а состояние остаётся `open`.

Ошибки опций и аргументов возвращаются непосредственно из `New`/`Scan`, канал при этом равен `nil`. Их можно получить через `errors.As(err, &validationError)`. Уже отменённый контекст возвращает `ctx.Err()` до запуска фоновой работы; `nil`-контекст отклоняется. Ошибки выполнения находятся в `Result.Err`; исходные причины доступны через `errors.Is`/`errors.As`.

## Конкурентность, результаты и отмена

Каждый `Scan` создаёт одного производителя заданий и `N` рабочих горутин. Производитель последовательно разрешает имена и постепенно выдаёт задания через небуферизованный канал. Для портов используется фиксированный битовый набор; декартово произведение целей, IP и портов в памяти не хранится.

Общий семафор экземпляра ограничивает **суммарное число TCP-подключений и DNS-запросов** всех одновременных `Scan` значением `N`. Поэтому число подключений также никогда не превышает `N`. У каждого DNS-запроса и подключения свой дочерний контекст с таймаутом; время ожидания семафора в него не входит. Родительский контекст ограничивает всю работу, включая ожидание и DNS. Лимит не является ограничением числа новых подключений в секунду.

Канал результатов имеет ёмкость `N`. Если читатель медленный, рабочие горутины ждут отправки, уже закрыв соединения и освободив общий семафор. Это ограничивает накопление результатов и позволяет другим сканированиям работать. На один вызов требуется `O(H + P + A + N)` дополнительной памяти, где `H` — число входных целей, `P <= 65535` — уникальные порты, `A` — адреса текущего DNS-имени. Число горутин растёт с количеством одновременно запущенных `Scan`, но сетевой лимит остаётся общим.

Без отмены возвращается ровно один результат для каждой уникальной тройки **цель / IP / порт**; при ошибке разрешения — один результат на **цель / порт**. Порядок результатов зависит от завершения операций и не гарантируется. Канал закрывается только после остановки производителя и всех рабочих горутин.

При отмене:

1. Производитель прекращает выдачу заданий, ожидание семафора прерывается.
2. Запущенные DNS/TCP-операции получают отмену контекста. Проверка контекста выполняется и после получения семафора. Операция, совпавшая по времени с отменой, получает уже отменённый контекст.
3. Результаты уже начатых операций, включая `canceled`, отправляются, если это не мешает завершению. Если канал заполнен, они могут быть отброшены.
4. Для неначатых заданий искусственные результаты не создаются. Уже помещённые в канал результаты остаются доступны.
5. Канал закрывается, даже если пользователь перестал его читать. После закрытия `ctx.Err()` позволяет обнаружить отмену или истечение общего срока. Отмена, пришедшая уже после успешного окончания, также видна через `ctx.Err()` — отдельного объекта состояния сканирования в API нет.

Такой контракт одновременно ограничивает память и обеспечивает завершение без читателя. Гарантировать доставку всех результатов при отмене и полностью остановившемся читателе через ограниченный канал невозможно. Для полного отчёта нужно читать канал до конца и не отменять контекст. Если требуется полный список непроверенных портов после отмены, его можно вычислить на стороне приложения из исходного набора и полученных результатов.

## Сборка и тестирование

Из корня репозитория на Go 1.25.5:

```sh
go test -race ./...
go vet ./...
```

Детектор гонок требует поддерживаемую платформу, `CGO_ENABLED=1` и C-компилятор; на Windows нужен совместимый GCC/MinGW. Модуль не использует сторонние зависимости, поэтому `go.sum` не требуется.

Тесты проверяют валидацию и объединение портов, нормализацию целей, несколько IP у одного имени, DNS-ошибки, системные коды, общий лимит одновременных сканирований, отмену в разных фазах, медленного/отсутствующего читателя и повторное использование. `testing/synctest` из Go 1.25 позволяет управлять временем в тестах таймаутов. Для управляемых ошибок подменяются только приватные функции dial/lookup; глобальное состояние не меняется. Интеграционные тесты используют локальные TCP-сокеты IPv4/IPv6, проверяют реальный отказ и наблюдают закрытие соединения со стороны сервера. IPv6-тест пропускается, если IPv6 loopback недоступен. Интернет и внешний DNS для тестов не нужны.

Подробности стандартной библиотеки: [net.Dialer.DialContext в Go 1.25.5](https://pkg.go.dev/net@go1.25.5#Dialer.DialContext), [net.Resolver.LookupNetIP](https://pkg.go.dev/net@go1.25.5#Resolver.LookupNetIP).
